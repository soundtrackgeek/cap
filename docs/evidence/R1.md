# R1 integration evidence

Execution is in progress. This document separates automated evidence from the
remaining installed/native acceptance work. No production journal is a fixture.

## Verified foundation and shared behavior

| Gate | Evidence |
| --- | --- |
| Native Rust CLI and pinned headless core | Windows CI builds without a sibling Capsule or color-cli checkout; runtime does not need Python. |
| Command grammar and output | Real-process tests cover help/version, reserved commands, literal `--`, JSON errors, ANSI-free machine output and output precedence. |
| Read-only journal commands | All eight read/diagnostic commands are connected; process tests cover pagination, hidden entries, safe config errors and explicit missing DB paths. Logical fixture snapshots remain unchanged. |
| Shared capture/reconciliation | [Independent process evidence](core-capture.md): concurrent writers, crash checkpoints, exact-once replay, replacement refusal, verified backup/FTS/reference checks and measured 15-second contention budget. |
| Context correctness | Injected provider/clock/cache tests cover fixed location, IP, Open-Meteo/MET, offline/disabled modes, cancellation, stale cache, historical rules and concurrent manual context. Root tests reject replacement before enrichment backup and clear unsaved provider candidates. |
| color-cli port | Eight palettes, five gradient modes, smoothstep and shimmer validated against pinned source fixtures; 24 engine tests and two source-reference tests. |
| Preferences/completions | Real-process persistence, output-mode and synthetic preview checks; PowerShell completion parsing; [Windows state-file race evidence](windows-state.md). |
| Console interruption | Owned ConPTY/console probes observed live frames and cursor restoration. Targeted child CTRL_BREAK returned130 after816ms; this is not a Windows Terminal visual recording. |
| Development latency | [20-sample core phase measurements](latency.md), with backup cost separated and a distinct help-startup observation. Full CLI timing remains pending. |
| Desktop regressions | Combined capture/context core passed74 desktop Rust tests, one existing live-provider smoke ignored, and strict Clippy. Frontend baseline passed42 tests across10 files using Vitest. |

The permanent core process probe runs in Windows CI. Runs before the CLI capture
package do not establish that `cap add` is ready: that command remains disabled
until its pending-state/receipt/context pipeline passes executable integration.

## Remaining R1 acceptance

- Integrate and independently exercise actual `cap add`, default/piped/file input,
  status, recovery, enrichment, failures after commit and real receipt effects.
- Measure actual CLI latency on owned synthetic1k/10k/100k journals, keeping backup,
  context and decoration costs distinguishable.
- Test clean-checkout packaging, installation from another directory, update,
  uninstall, PATH preservation and notices.
- Demonstrate a CLI entry in the native Capsule list/detail/search after refresh
  and restart, with metadata intact. Record the exact built desktop revision.
- Record Windows Terminal visual/keyboard behavior, narrow layout and resize.

An isolated native Capsule QA build was compiled and launched against a synthetic
journal. Desktop automation then returned `GetCursorPos failed: Access is denied
(0x80070005)` while the screen showed a screen saver. The request to unlock the
desktop is pending; no native UI success is inferred from compilation or browser
mock tests. Native validation resumes when the desktop is accessible.
