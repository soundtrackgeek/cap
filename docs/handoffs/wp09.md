# WP09 handoff: memory experiences

This package is based on cap `6f37567a456d270c852fda9e744221afb53603c6` and
Capsule core `279e1cbbba1bdee88e5a604e89b347f863fd88e5` in the isolated
`codex/cap-memory-core` worktree. The cap feature branch is
`codex/cap-memories`; the Capsule metrics branch is `codex/cap-memory-core`.

## Root wiring

The command registration owner should add these existing module declarations
and dispatch arms (the declarations are present in this feature worktree for
local tests):

```rust
// src/lib.rs
pub mod insights;

// src/commands/mod.rs
pub mod calendar;
pub mod garden;
pub mod on_this_day;
pub mod recall;
pub mod stats;

// src/ui/mod.rs
pub mod calendar;
pub mod garden;
pub mod unseal;
```

`app::execute` can dispatch the inline clap variants without changing the
central CLI structs:

```rust
Some(command @ Command::Recall { .. }) => commands::recall::run(command, &cli.global),
Some(Command::OnThisDay(args)) => commands::on_this_day::run(args, &cli.global),
Some(command @ Command::Calendar { .. }) => commands::calendar::run(command, &cli.global),
Some(command @ Command::Stats { .. }) => commands::stats::run(command, &cli.global),
Some(command @ Command::Garden { .. }) => commands::garden::run(command, &cli.global),
```

Prefer matching the command once and passing the borrowed variant rather than
constructing a temporary. The `run_at` helpers take an injected
`capsule_core::stats::NaiveDate` for deterministic tests. No cap Cargo
dependency is required beyond the reviewed core revision; the date type and
local clock are exposed by `capsule_core::stats`.

## Shared core wiring

Cherry-pick the Capsule branch first, then update cap's Git dependency and lock
file to its resulting immutable SHA. The core branch adds `stats` and
`mood_sentiment` modules and re-exports the metric DTOs from `capsule_core`.
The desktop worktree keeps the larger existing analytics adapter as
`legacy_stats` for dashboard/wrapped endpoints, while its writing-calendar
endpoint calls the shared `capsule_core::stats::get_writing_calendar`. The core
module uses the repository's bundled `src-tauri/mood_sentiment.json` and
preserves catalog overrides.

Key read-only APIs:

```rust
stats::memory_entries_for_database(path, MemoryQuery)
stats::recall_candidates_for_database(path, query, seed, max_candidates)
stats::on_this_day_for_database(path, date, include_hidden)
stats::memory_calendar_for_database(path, month, include_hidden)
stats::get_writing_calendar_for_database(path, year)
stats::memory_stats_for_database(path, period, today, include_hidden)
stats::memory_garden_for_database(path, today, include_hidden)
stats::milestone_crossing_for_database_with_timeout(path, today, uuid, include_hidden, timeout)
```

`MemoryQuery::page(limit, offset)` is explicit for full projections. Recall
reservoir-samples bounded metadata and fetches only selected bodies; calendar,
stats, garden, and milestone aggregates stream date/text rows without an
implicit cap. On-this-day pages similarly collect only metadata before fetching
the requested bodies. The crossing API streams one week summary and reads the
supplied committed UUID's exact word count before testing
`before < threshold <= after`. Its SQLite progress handler and busy wait share
the caller's monotonic timeout, and both reads run inside one deferred read
transaction snapshot. The cap receipt revalidates the frozen file identity
before querying, after querying, and immediately before sidecar publication;
replacement races are warning-only. It is safe to call after a confirmed commit
and never writes journal/gamification rows.

## Capture receipt hook

After commit, a capture consumer may call
`MemoryStateStore::milestone_receipt_for_committed` with the frozen database
path, `ResolvedCapsule.database_identity`, local date, and committed UUID. It
returns `MilestoneReceipt { glints, warnings, inputs }`. Daily is 50 words and
weekly is 500 words. Query, state lock, and atomic publish are best-effort and
bounded to about 200 ms; every failure is a warning and must not change save
success. A missing/unstable file identity suppresses glints. Do not call the
legacy `milestone_receipt` method for a save because it intentionally reports
totals without claiming a crossing when no committed UUID is available.

`MemoryStateStore` stores only cap-local memory state under
`CAP_CONFIG_HOME` (or the platform cap directory), keyed by canonical path and
stable file ID. The sidecar lock is persistent and uses `File::try_lock`, so a
killed process cannot leave a permanently blocking marker. State replacement
is flushed and same-directory atomic; a missing state file means no previous
recall and no emitted milestones.

## Human presentation hooks

`ui::unseal::recall_frame_at` animates only the short heading/date cue and adds
the authored body as a static final section; `ui::garden::garden_frame_at`
grows all seven data-backed plants over 400ms; and
`ui::calendar::calendar_frame_at` returns a count-brightened static grid. The
`animate_recall`, `animate_garden`, and `animate_calendar` helpers stream those
frames through `cap_effects::animate_frames_with_cancel`, which owns the TTY
guard, reserves the final terminal column, forces non-TTY static output, and
restores the terminal on cancellation/error. Root dispatch should call one
streaming helper for human output and not print its `CommandOutput.human` field
again; JSON/quiet/plain/reduced output can continue using the buffered result.


The synthetic command tests use `Fixture::from_profile(FixtureProfile::full())`
when all five rows are required, cover legacy FTS and hidden opt-in behavior,
inject leap/date boundaries, assert non-repeating recall, verify true milestone
crossing/once-only state, and compare the journal file bytes before/after reads.
They never point at a production database or mutate Capsule settings.
